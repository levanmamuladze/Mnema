# GitHub & Git glossary

Plain-language definitions of the terms you'll hear most.

- **Repository (repo)** — a project's folder, including all its files and
  the complete history of every change.
- **Commit** — a saved snapshot of changes, with a message describing what
  changed and why.
- **Branch** — an independent line of work. The default branch is usually
  called `main`.
- **Clone** — to download a full copy of a repository to your computer.
- **Fork** — your own copy of someone else's repository, under your account.
- **Pull request (PR)** — a proposal to merge changes from one branch into
  another, where teammates review before it's accepted.
- **Merge** — to combine the changes from one branch into another.
- **Rebase** — to replay your commits on top of another branch for a
  linear history.
- **Issue** — a tracked item: a bug, a task, or a feature request.
- **Label** — a tag you attach to issues and PRs (e.g. `bug`, `security-review`).
- **Milestone** — a group of issues/PRs working toward a goal or release.
- **GitHub Actions** — GitHub's built-in automation / CI-CD system.
- **Workflow** — an automated process defined in a YAML file under
  `.github/workflows/`.
- **Runner** — a machine that executes a workflow's jobs.
- **Secret** — an encrypted value (like an API token) stored in GitHub and
  injected into workflows at run time.
- **Release** — a packaged, versioned snapshot of a repo, often with
  downloadable assets.
- **GitHub Pages** — free static website hosting straight from a repo.
- **Gist** — a quick way to share small snippets of code or text.
- **Star** — a bookmark/endorsement of a repository.
- **Squash** — combining several commits into one when merging.
