# Git vs. GitHub — what's the difference?

People mix these up constantly. They are not the same thing.

## Git

**Git** is a *version-control system* — software you run on your own
computer. It was created by **Linus Torvalds in 2005** to manage
development of the Linux kernel. Git tracks every change to your files,
lets you branch and merge, and works completely offline. Git has no
website; it's a command-line tool (with many GUIs built on top).

Key Git concepts:

- **Commit** — a saved snapshot of your changes.
- **Branch** — an independent line of development.
- **Merge** — combining one branch's changes into another.
- **Clone** — copying a repository to your machine.
- **Remote** — a version of the repository hosted elsewhere.

## GitHub

**GitHub** is a *company and a website* (founded 2008, owned by Microsoft)
that **hosts Git repositories** and adds collaboration features Git itself
doesn't have: pull requests, issues, code review UI, Actions, and access
control.

## The analogy

If **Git** is the engine, **GitHub** is the car built around it — plus the
road network that lets everyone drive together. You can use Git without
GitHub. You cannot use GitHub without Git underneath.

## Quick comparison

| | Git | GitHub |
|---|---|---|
| What it is | Version-control software | Hosting + collaboration platform |
| Runs where | Your computer | The cloud (github.com) |
| Created | 2005, Linus Torvalds | 2008 |
| Needs internet | No | Yes |
| Pull requests | No (Git has none) | Yes |
